# Arcanea capability map

Resolve the user's outcome to an installed, verified capability. Preserve useful
ideas and unfinished work; a dated inventory never authorizes cleanup or release.

## Find the right source

- Product and locked canon: `arcanea-ai-app`; its `.arcanea/lore/CANON_LOCKED.md`
  owns official lore. The public `frankxai/arcanea` repository is a separate mirror.
- Creator skills: `arcanea-agent-skills`; use its registry, compiled plugin,
  installation guide and plugin doctor. Load the complete pack with references.
- Media creator MCP: local `arcanea-mcp`, remote `frankxai/arcanea-mcp-generate`.
  Run its release-readiness check before advertising npm installation.
- Worldbuilding MCP: `arcanea-ai-app/packages/arcanea-mcp`. It is a separate
  implementation; a matching executable name does not make the two interchangeable.
- Portfolio map: `arcanea-ecosystem`. Run `scripts/audit-capabilities.mjs` from
  that repository with explicit repository and skill roots.
- Developer, commons and research sites: `arcanea-domain-portals`.
- World Proof front door: `arcanea-academy`; creative media surface: `arcanea-studio`.
- Public `arcanea-plugins` and `arcanea-plugin-sdk` have upstream LobeHub heritage.
  Inspect their actual contracts before treating them as a Codex or MCP package.

Find these child repositories under the user's configured estate. Verify exact
Git root, origin, branch, owned files and current task before writing. Never
infer a repository location from a historical home-folder path or search a whole
home directory or drive. Follow the host's workspace routing procedure.

## Audit in six steps

1. Inventory sources and versions. Count files with a command; distinguish source
   skills, generated copies, stubs and companion skills rather than summing them
   as unique capabilities. Read requested skills and required references.
2. Inspect the host's plugin list. Record namespace, source, version and enabled
   state. A plugin in a cache may be disabled or unavailable to the current task.
3. Compare installed bytes against the verified pack. Use the canonical doctor;
   do not edit cache files. Preserve full custom skills and unexpected links.
4. For MCP, distinguish a JSON contract, implemented server, successful handshake,
   safe read-only tool result, provider-backed action and externally installable
   release. Prove each separately. Never expose environment values in an audit.
5. Inspect GitHub and the hosting provider, then probe the exact live routes.
   A successful preview is not proof that the production domain serves it.
6. Fix the smallest demonstrated gap, run relevant regression checks, refine the
   result, obtain independent review before release and record commit/PR/evidence.

## Choose capabilities by the work

Use the installed creation router for a World Proof, scene, continuity audit or
Guild contribution. Keep independent creator worlds separate from official Arcanea
canon. Generated additions are proposals. Use the host's actual available model
for synthesis; require empirical evaluations before claiming one model improves
quality. Use a connected media tool only when its capability, cost and authority
are established for this task.

Load skills on demand. Keep local MCP servers scoped to the task that needs them.
Before builds, browser work or additional agents, honor the machine admission
result. Protected processes and unfinished tasks are not cleanup targets.

## Handoff

Report measured inventory, improvements, validation and exact artifacts. Separate
installed, enabled, tested, published and live. Keep unresolved capability work
open with its next bounded action; do not turn a contract into a product claim.
